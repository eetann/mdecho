# 約物・和欧間のアキのサンプル

日本語の中に英単語やインラインコード、数字が混ざったときに、その境目へ自動でアキ(四分アキ)が入るかどうかを見比べるためのサンプルです。
あわせて、行頭に来た開き括弧が詰められるかどうかも確かめられます。

Chromium系(Chrome / Edge)とSafari 18.4以降で効きます。
未対応のブラウザではこれまでどおりの字間になるだけで、表示が崩れることはありません。

## 比較用の文章

1. 設定ファイルはTypeScriptではなくJSONCで書くので、コメントを残したまま共有できます。
2. インラインコードの`contentWidth`や`--no-split-sentences`が文の途中に出てくると、前後の日本語との境目がいちばん目立ちます。
3. Node.jsのバージョンは20.19.0以上が必要で、Bunは1.2系で動作を確認しています。
4. AIが生成した設計書ではmdechoやremark-gfmのような固有名詞が地の文に混ざるため、1文あたりの境目の数が多くなりがちです。
5. 「見出し」や『引用』のような鉤括弧が行頭に来たとき、左端が揃って見えるかどうかも確認してください。
6. 括弧の中に英語を入れる場合(たとえばprogressive enhancementのように)、括弧の外側と内側の両方に境目ができます。
7. 数字が続く文、たとえば1個、12個、345個と並ぶ箇所では、読点と数字のあいだの詰まり具合が変わります。
8. HTTPステータスの404や500、ポート番号の3000のように、数字だけが飛び出す書き方でも同じように境目ができます。
9. 「`--no-open`を付けるとブラウザは開かない」のように、鉤括弧とインラインコードが隣り合うと差がはっきり出ます。
10. 閉じ括弧と読点が連続する場合(「ここまで」、のような並び)の詰め方は、この設定とは別に既定で効いています。

## 行頭に来る括弧

「句点ごとの改行」が有効だと1文ずつが行頭から始まるため、開き括弧で始まる文の左端が揃うかどうかを確かめやすくなります。
『二重鉤括弧』で始まる文も同じです。
(半角の括弧)で始まる文は詰めの対象外なので、比較の基準として並べています。

## 箇条書きの中

- `mdecho -f review.md`のようにコマンドを書くと、行頭のインラインコードと日本語の境目ができます。
- 設定はデフォルトで`~/.config/mdecho/config.jsonc`に保存され、CLIフラグのほうが優先されます。
  - ネストした項目でも同じで、contentWidthを1024pxから720pxへ変えても境目の扱いは変わりません。

## 引用の中

> レビューコメントにはTypeScriptの型エラーやESLintの警告など、英単語がそのまま貼られることが多いです。
> 「引用の中でも同じように効いているか」を確かめてください。

## 表の中

| 項目 | 説明 |
| :--- | :--- |
| text-autospace | 日本語とLatin文字・数字の境目に四分アキを入れます。Chrome 140以降とSafari 18.4以降で有効です。 |
| text-spacing-trim | 行頭に来た「開き括弧」の左半分を詰めます。Chromium系が中心で、値によってはどのブラウザも未実装です。 |

## コードブロックの中

コードブロックは等幅の桁が揃っていてほしいので、この設定を打ち消しています。
下のコメント行の字間が、前後で変わっていないことを確認してください。

```ts
// 日本語のcommentとcodeが混ざった行。ここは字間が変わらない
export function greet(name: string): string {
  // version 2.0から利用できる
  return `こんにちは、${name}さん。`;
}
```
