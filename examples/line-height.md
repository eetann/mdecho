# 本文の行間のサンプル

本文の行間(`line-height`)を変えたときに、段落の読みやすさがどう変わるかを見比べるためのサンプルです。
1.5〜1.6はラテン文字を基準にした値で、漢字とかなが詰まって並ぶ日本語の本文では行が近すぎて隣の行へ視線が滑りやすくなります。
1行が長い段落ほど差が出るので、ウィンドウ幅や設定モーダルの本文の幅を広げた状態でも眺めてください。

## 比較用の文章

1. AIが生成した設計ドキュメントは一文が長くなりやすく、画面の幅いっぱいまで文字が並んだ状態で行間が詰まっていると、いま読んでいる行がどれなのかを見失って同じ行を二度読みしてしまうことがあります。
2. 漢字とひらがなは文字の重心が上下に散らばっていて、ラテン文字のように小文字の高さで視線の高さが揃わないため、行と行のあいだに余白が少ないと文字の塊が縦につながって見えてしまいます。
3. 行の終わりから次の行の先頭へ視線を戻す動きは、行間が広いほど目的の行を捉えやすくなり、長い段落を続けて読んだときの疲れ方がはっきり変わってきます。
4. 句点ごとの改行が有効なときは一文ごとに行が変わるため、一行が短くなるぶん行の数が増え、段落全体が縦に細長い塊になって行間の詰まり具合がより目立つようになります。
5. 括弧や鉤括弧、ダッシュのような約物が多い文章では、記号が行の上寄りや下寄りに来るので、行間が狭いと上下の行の記号どうしが近づいて視覚的にうるさくなります。
6. 英数字が混ざった文、たとえばTypeScriptの型定義やNode.jsのバージョン番号が地の文に並ぶ場合は、ラテン文字のディセンダが下の行へ近づくぶん、行間の余裕がそのまま読みやすさに効いてきます。
7. `--no-split-sentences`のようなインラインコードは背景色が付いていて行の中で目立つため、行間が狭いと上下の行にある背景の帯どうしがくっついて見え、文字よりも帯のほうへ視線が引っ張られます。
8. 箇条書きの項目がそれぞれ複数行に折り返すような長さになると、項目の中の行間と項目どうしの間隔が近い値になってしまい、どこまでが一つの項目なのかが読み取りにくくなります。
9. 引用ブロックのように左側に罫線が引かれている場所では、本文よりも幅が狭くなって折り返しの回数が増えるため、行間が詰まっているときの読みにくさが本文以上に出てしまいます。
10. 見出しの行間は本文とは別に詰めてあり、二行に折り返すような長い見出しでも一つの塊として読めるようにしているので、本文の行間を広げても見出しの見え方は変わりません。

## 見出しが二行に折り返すくらい長いときに行間がどう見えるかを確かめるための見出し

見出しの直後の段落です。
見出しの行間は本文とは別に指定されているため、本文の行間を変えても見出しの詰まり具合は変わりません。
見出しと本文の行間の差がはっきりするほど、文書の構造が目で追いやすくなります。

## 箇条書きの中

- 箇条書きの項目でも本文と同じ行間が効きます。この項目のように二行以上へ折り返す長さになると、項目の内側の行間と項目どうしの間隔のバランスが見えてきます。
- 短い項目。
- ネストした項目でも同じです。
  - インデントのぶんだけ本文の幅が狭くなるので折り返しの回数が増え、行間の違いがいちばん見つけやすい場所になります。

## 引用の中

> レビューコメントをそのまま引用として貼り付けると、左の罫線と余白のぶんだけ本文が狭くなるので、同じ文章でも折り返しの回数が増えます。
> 行が増えるぶん行間の詰まり具合が目立ちやすく、本文との差を見比べる場所として向いています。

## 表の中

| 項目 | 説明 |
| :--- | :--- |
| 行間 | セルの中の文章にも本文と同じ行間が効きます。列の幅は内容にあわせて決まるため、長い説明文を入れると表の中でも折り返しが起きて行が増えます。 |
| 行の高さ | 行が増えるとセルの高さが変わるので、表全体の縦の長さも行間の値によって変わります。 |

## コードブロックの中

コードブロックは等幅の桁を詰めて見せたいので、本文とは別の行間を指定しています。
下のコードの行間が前後で変わっていないことを確認してください。

```ts
// 日本語のコメントを書いても、ここの行間は本文とは別に指定されている
export function greet(name: string): string {
  const message = `こんにちは、${name}さん。`;
  return message;
}
```
