# 日本語の折り返しサンプル

本文の折り返しが文節の区切りで入るかどうかを見比べるためのサンプルです。
ウィンドウ幅を変えたり、設定モーダルで本文の幅を変えたりしながら、各行の終わりがどこで切れるかを眺めてください。

Chromium系(Chrome / Edge)では文節の区切りで折り返します。
SafariやFirefoxは未対応なので、これまでどおり文字単位の折り返しに戻るだけで、表示が崩れることはありません。

## 比較用の文章

1. AIが生成したレビュー用のドキュメントは一文が長くなりがちで、画面の幅いっぱいまで文字が並ぶと、どこで意味の切れ目が来るのか読み取りにくくなります。
2. 文節の区切りで折り返すと、行の終わりで単語や助詞が途中で切れなくなるため、次の行の先頭へ視線を移すときの負担が小さくなります。
3. たとえば「設定ファイルを読み込んだあとにサーバーがスタイルを注入します」という文では、「読み込んだ」と「あとに」のどちらで切れるかによって読みやすさが変わります。
4. この挙動に対応しているのはChromium系のブラウザだけですが、対応していないブラウザでも従来と同じ折り返しになるだけなので、見た目が壊れる心配はありません。
5. 長いURL、たとえば https://example.com/docs/configuration/line-break/auto-phrase.html のようなものは、これまでどおり途中で折り返して画面からはみ出さないようにします。
6. 英数字と日本語が混ざった文、たとえばTypeScriptのコンパイラオプションをJSONCで書くときの話では、英単語側の切れ目は英語のルールのまま保たれます。
7. 句読点が続く場合や、括弧(かっこ)が入り組んでいる場合でも、行頭に句点や閉じ括弧が来ないようにする禁則処理はこれまでと同じように働きます。
8. 箇条書きの中の文章でも、引用ブロックの中の文章でも同じ設定が効くので、ドキュメント全体を通して折り返しの見え方が揃います。
9. コードブロックの中は等幅フォントのまま横スクロールするため、この設定の影響を受けず、書いたとおりの位置で改行されます。
10. 本文の幅を変えたときにそれぞれの行がどこで切れるのかを見比べると、設定を入れる前と後の違いがいちばんはっきり分かります。

## 箇条書きの中

- 見出しの直後に置いた短い説明文でも、折り返しが起きるくらいの長さになれば文節の区切りが効いていることを確認できます。
- ネストした項目でも同じです。
  - インデントのぶんだけ本文の幅が狭くなるので、かえって折り返しの違いが見つけやすくなります。

## 引用の中

> レビューコメントを引用として貼り付けると、左の罫線のぶんだけ本文が狭くなるため、短い文でも折り返しが発生します。
> 引用の中でも文節の区切りで折り返されているかどうかを確かめてください。

## 表の中

| 項目 | 説明 |
| :--- | :--- |
| 折り返し | セルの幅は内容にあわせて決まるため、長い説明文を入れると表の中でも折り返しが起きます。 |
| 禁則処理 | 行頭に句読点や閉じ括弧が来ないようにする処理は、この設定とは別に働きます。 |

## コードブロックの中

コードブロックは横スクロールするので、この設定の影響を受けません。

```ts
// 日本語のコメントを書いても、ここでは折り返しが起きずに横へ伸びていきます。
export function greet(name: string): string {
  return `こんにちは、${name}さん。`;
}
```
