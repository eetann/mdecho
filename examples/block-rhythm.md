# 段落と箇条書きのサンプル

説明の段落と箇条書きが交互に続くときの、塊の境目を見比べるためのサンプルです。
AIが生成したMarkdownは「説明の段落 → 箇条書き → 次の説明の段落」の繰り返しになりやすく、段落と箇条書きの上下が同じ幅で空いていると、どこからどこまでが一つの話題なのかが読み取れません。

段落とその下の箇条書きがひと塊に見えるか、箇条書きが終わって次の話題に移ったことが分かるかを眺めてください。

## 比較用の文章

1. AIが生成したドキュメントは、まず結論を一段落で述べてから、その根拠や手順を箇条書きで並べる形になることがほとんどです。
2. 段落の下の箇条書きはその段落の続きなので、間が空いているほど「別の話が始まった」という誤った手がかりを読み手に与えてしまいます。
3. 逆に箇条書きが終わったあとの段落は次の話題に移っていることが多く、こちらは離れているほど話の切り替わりが読み取れます。
4. 段落の下も箇条書きの下も同じ幅で空いていると、箇条書きが上の段落にぶら下がっているのか下の段落の前置きなのかが判別できません。
5. 拾い読みをするときは、まず塊の単位を目で探してから中身を読むので、塊の境目がどこにあるのかが読む速さに直結します。
6. 段落の下を詰めすぎると今度は箇条書きが段落の一部のように見えてしまうため、項目どうしの間隔よりは狭く、ゼロよりは広いあたりに収めます。
7. 箇条書きの下を空けすぎると、ページ全体が間延びして一画面に入る情報量が減るので、段落どうしの間隔より少し広い程度に留めます。
8. 段落・箇条書き・段落の三つが並ぶ場所では、上の隙間と下の隙間の差そのものが「この箇条書きは上に属している」という手がかりになります。
9. 番号付きリストでも中黒の箇条書きでも同じ扱いにするので、手順を並べた場所と根拠を並べた場所で見え方が揃います。
10. 項目どうしの間隔(TASK-0013)とあわせて見ないと、外側だけが広がって間延びしたり、内側だけが詰まって一覧に見えなくなったりします。

この10項目は上の段落にぶら下がっていて、ここから先は別の話です。上下の隙間が違って見えるかどうかがいちばんの見どころになります。

## 説明の段落と箇条書きの繰り返し

設定ファイルを置く場所は、実行するユーザーのホームディレクトリの下になります。次のどちらかに置いてあれば読み込まれます。

- `~/.config/mdecho/config.jsonc`
- `~/.mdecho/config.jsonc`

読み込みはサーバーの起動時に一度だけ行われます。起動したあとに設定ファイルを書き換えた場合は、次のように扱われます。

- 本文の再描画には反映されない
- 設定モーダルから保存し直すと反映される

フォントの指定は、ブラウザが持っているフォントの中から前から順に探していく形です。見つからなかった場合の動きは次のとおりです。

- 指定した名前のフォントが無ければ、既定のスタックへ順に落ちていく
- 既定のスタックも見つからなければ、OSのsans-serifが使われる

行の折り返しと字間の設定は、ブラウザによって効いたり効かなかったりします。対応していないブラウザでの見え方は次のようになります。

- Chromium系は文節の区切りで折り返し、日本語と英数字の境目にアキが入る
- SafariとFirefoxは従来どおりの折り返しと字間に戻るだけで、表示は崩れない

ここまでが設定の話で、ここから先は表示の話です。段落と箇条書きが四つ続いたあとで、話題が切り替わったことが分かるでしょうか。

## 短い段落と短い箇条書きが交互に来る場合

一つ目の話です。

- 一つ目の項目。
- 二つ目の項目。

二つ目の話です。

- 一つ目の項目。
- 二つ目の項目。

三つ目の話です。

- 一つ目の項目。
- 二つ目の項目。

文章が短いぶん、隙間の差がそのまま塊の見え方になります。

## 番号付きリストの手順

インストールから起動までの手順です。上から順に実行してください。

1. `bun install` で依存をインストールする。
2. `bun run build` でCLIとクライアントをビルドする。
3. `bun run src/index.ts -f review.md` で起動する。

手順が終わったあとの注意点です。ここが箇条書きの下の段落にあたります。

## 箇条書きが続けて二つ並ぶ場合

前置きの段落です。この下に箇条書きが二つ、あいだに段落を挟まずに並びます。

- 一つ目の箇条書きの項目です。
- 二つ目の項目です。

1. 続けて番号付きリストが来ます。
2. 二つ目の項目です。

箇条書きが二つ続いたあとの段落です。リストとリストのあいだと、リストと段落のあいだの見え方を比べる場所です。

## 見出しが挟まる場合

段落の下にすぐ見出しが来る場合です。

### 小見出し

見出しの下の段落です。この下の箇条書きは見出しの中の話になります。

- 見出しの中の項目です。
- 二つ目の項目です。

見出しの中の段落です。見出しの余白(上1.5em)と箇条書きの余白が並ぶ場所を確かめてください。

## 引用の中

> レビューコメントを引用として貼り付けると、その中でも段落と箇条書きが交互に並びます。
>
> - 引用の中の項目です。
> - 二つ目の項目です。
>
> 引用の中の段落です。罫線で囲まれているぶん、外の本文より塊の境目が分かりやすくなっているかを見ておきます。

## 項目の中に段落がある場合

いわゆるルーズリストです。項目の中の段落と、項目どうしの区切りが並びます。

- 項目の中の一つ目の段落です。

  項目の中の二つ目の段落です。ここは項目の内側なので、塊の境目とは別の切れ目になります。

  - 項目の中の箇条書きです。この上の段落との隙間も、外側と同じ扱いになります。
  - 二つ目の項目です。

  箇条書きのあとの段落です。項目の中でも同じ差が付いているかを確かめてください。

- 二つ目の項目です。

ルーズリストのあとの段落です。

## コードブロックや表を挟む場合

段落の下にコードブロックが来る場合です。箇条書きとは別の扱いになります。

```ts
export function greet(name: string): string {
  return `こんにちは、${name}さん。`;
}
```

コードブロックのあとの段落です。この下に表が来ます。

| 場所 | 変わるもの |
| :--- | :--- |
| 段落の下 | 箇条書きが始まるまでの隙間 |
| 箇条書きの下 | 次の段落が始まるまでの隙間 |

表のあとの段落です。コードブロックと表の上下は今までどおりかを確かめる場所です。
