# 設定ファイル

mdechoはグローバルな設定ファイルを1つだけ読み込みます。プロジェクトごとの設定はありません。

## 画面から設定する

ツールバー右上の歯車アイコンを押すと設定モーダルが開き、改行の扱い・本文の見え方・フォントを変更できます。

### 改行

- 2つのトグルはそれぞれ `lineBreak.splitSentences` / `lineBreak.singleNewline` に対応します
- 改行の扱いはサーバー側でHTMLを組み立てるときに決まるため、保存すると自動でページを読み込み直します(コメントは残ります)
- 起動時に `--no-split-sentences` などのコマンドラインオプションを付けていた場合、そちらが優先されます。保存はできますが、効くのは次回起動からです(モーダルにもその旨が出ます)

### レイアウト

- 本文の幅・文字サイズ・行の高さを、スライダーか数値入力で変えられます。動かすとその場で背景の表示に反映されます(保存しなくても見た目で確かめられます)
- スライダーは決まった刻みで動きます。もっと細かく合わせたいときは隣の数値入力に直接書いてください
- 「保存」で `layout.contentWidth` / `layout.fontSize` / `layout.lineHeight` として設定ファイルへ書き込みます

### フォント

- 選んだ内容はその場で背景の表示に反映されます(保存しなくても見た目で確かめられます)
- 入力欄をクリックすると、そのマシンのフォントが候補に出ます(`mdecho font-ls` と同じ一覧)
- 候補は日本語名でも絞り込めます(「ゴシック」と入力すると `Yu Gothic` などが出ます)
- 候補は `↑` `↓` で選んで `Enter` で追加できます。一覧に無いフォント名はそのまま入力して追加できます
- 追加したフォントは `↑` `↓` で優先順位を入れ替え、`×` で削除します
- 「保存」で設定ファイルへ書き込みます。既存のコメントや並びはそのまま残ります
- 「キャンセル」(または Esc)で編集前の状態に戻ります

設定ファイルがまだ無ければ、保存時に `~/.config/mdecho/config.jsonc` を作ります。

YAMLやTypeScriptで設定ファイルを書いている場合は、JSONCとして書き戻すと壊れてしまうため保存が無効になります。その場合は手で編集してください。

## 置き場所

```
~/.config/mdecho/config.jsonc
```

`$XDG_CONFIG_HOME` が設定されている場合は `$XDG_CONFIG_HOME/mdecho/config.jsonc` を読みます。

拡張子は `.jsonc` のほか `.json` / `.json5` / `.yaml` / `.yml` / `.toml` / `.js` / `.ts` も使えます。コメントを書けるので `.jsonc` を推奨します。

設定ファイルが無ければ既定値で起動します。読み込めた場合は起動時に `Loaded config from ...` を表示します。

## 例

```jsonc
{
  "font": {
    // 本文(コードブロック以外)のフォント
    "body": ["Inter", "BIZ UDPGothic"],
    // コードブロック・インラインコードのフォント
    "code": ["JetBrains Mono", "BIZ UDGothic"],
  },
  "lineBreak": {
    // 句点(。)ごとに表示上の改行を入れる
    "splitSentences": true,
    // 単一改行(Enterキー1回)をそのまま表示上の改行にする
    "singleNewline": true,
  },
  "layout": {
    // 本文の幅(px)
    "contentWidth": 1024,
    // 本文の文字サイズ(px)
    "fontSize": 16,
    // 本文の行の高さ(文字サイズに対する倍率)
    "lineHeight": 1.75,
  },
}
```

## 使えるフォント名を調べる

```bash
mdecho font-ls
```

そのマシンでブラウザが使えるフォント名を一覧表示します。名前で絞り込むときはgrepなどに流してください。

```bash
mdecho font-ls | grep -i gothic
```

括弧が付いている行は、同じフォントを指す別名です。設定ファイルには**括弧の前の名前**を書いてください。

```
BIZ UDPGothic (BIZ UDPゴシック)
```

WSLで使っている場合、描画するのはWindows側のブラウザなので、Linux側ではなくWindowsのフォントを一覧します。

## `font`

CSSの `font-family` と同じく、**前から順に試して、そのフォントが無ければ次のものが使われます**。

| キー | 説明 |
| --- | --- |
| `font.body` | 本文(コードブロック・インラインコード以外)のフォント |
| `font.code` | コードブロックとインラインコードのフォント |

どちらも文字列の配列で指定します。1つだけなら文字列でも書けます。

```jsonc
{
  "font": { "body": "Inter" }
}
```

指定したフォントは、mdechoが持つ既定のフォントスタックの**手前**に差し込まれます。そのため一部のフォントだけを指定しても、日本語や絵文字は既定のフォントにフォールバックします。

例えば `"body": ["Inter"]` と書いた場合、実際の `font-family` は次のようになります。

```css
font-family: Inter, -apple-system, BlinkMacSystemFont, "Hiragino Sans", /* ...既定のスタック... */;
```

`font.body` と `font.code` は片方だけの指定でも構いません。指定しなかったほうは既定のままです。

## `lineBreak`

Markdownのどこで**表示上の改行**を入れるかを決めます。元のMarkdownファイルは書き換えません。

| キー | 既定 | 説明 |
| --- | --- | --- |
| `lineBreak.splitSentences` | `true` | 句点(。)ごとに表示上の改行を入れる |
| `lineBreak.singleNewline` | `true` | 単一改行(Enterキー1回)をそのまま表示上の改行にする |

どちらも真偽値です。片方だけ書いても構いません。書かなかったほうは既定値のままです。

```jsonc
{
  // 句点では切らず、書いた改行だけをそのまま表示する
  "lineBreak": { "splitSentences": false }
}
```

### `splitSentences`

有効にすると、1つの段落でも句点ごとに1文ずつ表示されます。行単位のコメントを文ごとに付けられるようになるため、既定で有効です。

分割されるのは段落の地の文だけで、見出し・表のセル・コードブロック・インラインコードの中の句点では分割されません(太字やリンクの中の句点も対象外)。

```markdown
AはBです。そしてBがCなのです。
```

```text
true  … 「AはBです。」「そしてBがCなのです。」が別々の行として表示される
false … 1行のまま表示される
```

### `singleNewline`

有効にすると、Enterキー1回の改行がそのまま `<br>` として表示されます。無効にすると、Markdown本来の扱い(空白としてつながり、改行するには行末に半角スペース2個か空行が要る)に戻ります。

```markdown
1行目
2行目
```

```text
true  … 2行として表示される
false … 「1行目 2行目」と1行につながる
```

なお、この設定が効くのは本文の表示だけです。コメント欄に書いた文章は、入力したとおりに改行されます。

### コマンドラインオプションとの関係

`--split-sentences` / `--no-split-sentences` と `--single-newline` / `--no-single-newline` は、この `lineBreak` と同じ項目です。**コマンドラインで明示したときだけ設定ファイルより優先されます**。

```bash
# 設定ファイルで splitSentences: true にしていても、この起動中は分割しない
mdecho -f review.md --no-split-sentences
```

## `layout`

本文をどのくらいの幅・大きさ・行間で表示するかを決めます。読みやすい値は人によって違うので、好みに合わせて調整してください。

| キー | 既定 | 範囲 | 説明 |
| --- | --- | --- | --- |
| `layout.contentWidth` | `1024` | 480〜2400 | 本文の最大幅(px) |
| `layout.fontSize` | `16` | 12〜32 | 本文の文字サイズ(px) |
| `layout.lineHeight` | `1.75` | 1.2〜2.4 | 本文の行の高さ(文字サイズに対する倍率) |

範囲から外れた値は警告を出して両端に丸めます。`contentWidth` と `fontSize` は整数に、`lineHeight` は小数2桁に丸めます。

```jsonc
{
  "layout": {
    // ワイドディスプレイで表も見やすくしたいとき
    "contentWidth": 1440,
    // 少し大きめの文字でゆったり読みたいとき
    "fontSize": 18,
    "lineHeight": 1.9,
  },
}
```

### `contentWidth`

画面の右端は目次のために空けてあり、**その残りの幅に対して本文が中央寄せ**されます。そのため本文の左右の余白は同じ幅になります。目次が出ない幅の画面(1280px未満)や、見出しが無くて目次が出ないページでは、画面全体に対して中央寄せします。

`contentWidth` が指す幅には、左右の余白(各32px)と行番号のガターも含みます。画面が `contentWidth` より狭いときは、画面の幅いっぱいに表示します。

### `fontSize`

本文と行番号の文字サイズです。見出し・コードブロック・行番号はどれもこの値を基準にした比率で決まるため、ここを変えると読む列がまとめて拡縮します。ツールバーと目次は変わりません。

行番号のガターも文字サイズに比例して広がるので、`fontSize` を上げると同じ `contentWidth` でも本文に使える幅は少し狭くなります。文字を大きくして1行の文字数を保ちたい場合は、`contentWidth` も一緒に広げてください。

### `lineHeight`

行1つぶんの高さを、文字サイズに対する倍率で指定します。1.5〜1.6はラテン文字を基準にした値で、漢字とかなが隙間なく並ぶ日本語の本文では行がくっついて見えます。日本語の目安は1.7〜2.0です。

広げすぎると段落の切れ目が行間に埋もれます(段落の下の余白は行の高さと一緒には伸びないため)。また1.9あたりから本文の行送りが見出しの行送りを超えて、見出しより本文のほうが緩く組まれた見た目になります。

見出しとコードブロックの行間は別に決めてあるので、この設定では変わりません。

## 設定が効かないとき

- 起動時に `Loaded config from ...` が表示されるか確認してください。表示されない場合、パスが違うか構文エラーです。
- 構文エラーがある場合は `設定ファイルに構文エラーがあるため、既定の設定で起動します` と警告が出ます。
- 未知のキーを書くと `設定に未知のキーがあります: ...` と警告が出ます。タイポを疑ってください。
- `lineBreak` が効かないときは、起動時に `--no-split-sentences` などを付けていないか確認してください。コマンドラインでの指定が優先されます。
- 指定したフォントがそのマシンに入っていない場合は、次のフォントへフォールバックします。ブラウザの開発者ツールで実際に適用されている `font-family` を確認できます。
